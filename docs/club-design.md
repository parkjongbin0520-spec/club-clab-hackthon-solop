# 동아리 웹앱 UI 벤치마킹 — Tooplate 템플릿 분석

## 문서 성격

이 문서는 **당장 구현할 기능 명세가 아니라 참고 자료**다. 현재 프로젝트(`CLAUDE.md`)는
서버/DB 없이 localStorage만 쓰는 단일 페이지 활동 기록 앱이며, 화면 구성도 "등록 폼 →
검색/필터 바 → 카드 리스트" 한 흐름으로 고정되어 있다. 이 문서에서 다루는 Hero/Menu/News&Events
같은 다중 섹션 구조는 그보다 화면 수와 정보량이 많은 **확장판을 염두에 둔 벤치마킹**이며,
실제 적용 여부와 시점은 별도 논의 후 결정한다.

분석 대상:

- [Tooplate 2141 Minimal White](https://www.tooplate.com/view/2141-minimal-white) — 섹션 디자인(색상/타이포/레이아웃) 참고
- [Tooplate 2129 Crispy Kitchen](https://www.tooplate.com/live/2129_crispy_kitchen) — 페이지 구성(Hero/Menu/News&Events) 참고

## 1. Tooplate 2141 "Minimal White" — 섹션 디자인 분석

전체 톤: 흑백(black & white) 컬러 스킴, 넉넉한 여백, 산세리프 타이포그래피, 스크롤 시
페이드인 애니메이션과 호버 인터랙션 위주의 절제된 디자인.

| 섹션          | 내용                                                    | 시각 스타일                  |
| ----------- | ----------------------------------------------------- | ----------------------- |
| Nav         | 로고 + 수평 메뉴(HOME/ABOUT/SERVICES/CONTACT), 모바일에서 햄버거 전환 | 고정(sticky) 네비게이션, 최소 장식 |
| Hero        | 큰 헤드라인 + 부제 + 명언(quote) + CTA 버튼 1개                   | 흰 배경, 검은 타이포, 비대칭 그리드   |
| Stats       | 숫자 지표 나열(만족도%, 프로젝트 수, 경력 연차 등)                       | 큰 숫자 + 작은 라벨, 가로 나열     |
| Philosophy  | 핵심 원칙 3가지                                             | 텍스트 위주, 아이콘 없이 여백으로 구분  |
| Process     | 4단계 리니어 플로우 (Discover→Reduce→Refine→Deliver)          | 순서가 있는 가로/세로 스텝         |
| Core Values | 4개 아이콘+텍스트 그리드                                        | 정사각형 그리드 카드             |
| Services    | 3개 카드(설명+링크)                                          | 비대칭 그리드, 호버 시 강조        |
| Footer      | 연락처 + 메시지 폼                                           | 심플한 2단 레이아웃             |

가져다 쓸만한 원칙: **비대칭 그리드로 콘텐츠 위계 만들기**, **스크롤 페이드인으로 밋밋함 완화**,
**카드 하나당 정보량 최소화**.

## 2. Tooplate 2129 "Crispy Kitchen" — 페이지 구성 벤치마킹

| 섹션            | 구조                                                              | 비고                      |
| ------------- | --------------------------------------------------------------- | ----------------------- |
| Header        | 로고 + 메뉴(Home/Story/Menu/Updates/Contact) + "Reservation" CTA 버튼 | CTA가 헤더에 항상 노출          |
| Hero          | 배경 이미지 + 제목 + **"4.4/5 · 1,206+ Reviews"** 평점 배지 + 위치정보         | 평점을 히어로에 바로 노출하는 패턴이 핵심 |
| Carousel      | 슬라이드별 아이템(이미지+가격+평점) + 이전/다음 버튼, 비디오 포함                         |                         |
| Special Menus | 6개 그리드 카드(이미지+제목+가격+평점+리뷰수), Breakfast/Lunch/Dinner 카테고리 구분     | 실제 메뉴 페이지도 동일 카드 패턴 반복  |
| News & Events | 5개 카드(썸네일+제목+태그+날짜), 태그: Featured/Promotions/News/Meeting       |                         |
| Footer        | 주소/영업시간/전화/소셜                                                   |                         |
| Reservation   | 별도 모달 폼(이름/이메일/전화/인원/날짜/시간/요청사항)                                |                         |

## 3. 동아리 웹앱 요구사항과의 매핑

사용자가 제시한 요구사항:

- Hero: 최근에 올렸거나 평가 점수가 좋은 게시물 노출
- Menu: 사용자가 올린 게시물 확인
- News & Events: 이슈나 해야 할 일
- 게시물 수정/삭제는 카드 클릭 → 상세 진입 후에만 가능

| 요구사항                   | 적용할 패턴                                                                              | 출처                             |
| ---------------------- | ----------------------------------------------------------------------------------- | ------------------------------ |
| Hero (최근/고평점 게시물)      | 배경 이미지 위에 "★4.6/5 · 32명 평가" 형태의 평점 배지 + 제목. 최근 글 ↔ 인기 글 전환은 Carousel 구조 차용          | Crispy Kitchen 평점 배지, Carousel |
| Hero 여백/타이포            | 과밀하지 않게 넉넉한 여백과 절제된 타이포로 배지·제목만 강조                                                  | Minimal White                  |
| Menu (내 게시물 확인)        | 그리드 카드(썸네일+제목+평점+메타정보) + 상단 카테고리 탭. 원본 Breakfast/Lunch/Dinner 탭을 "공지/사진/자유글" 등으로 치환 | Crispy Kitchen Special Menus   |
| 카드 클릭 → 수정/삭제          | 카드 전체를 클릭 가능한 링크로 만들어 상세 페이지로 이동, 상세 페이지에서만 수정/삭제 버튼 노출                             | Minimal White 카드 호버 강조 + 요구사항  |
| News & Events (이슈/할 일) | 카드(썸네일+제목+태그+날짜) 그대로 사용. 태그만 "긴급/진행중/완료/공지"로 치환                                     | Crispy Kitchen News & Events   |

## 4. 현재 프로젝트 범위와의 관계

- 현재 MVP(`CLAUDE.md` Session 1~5)는 등록 폼 + 검색/필터 + 카드 리스트만으로 구성된
  단일 화면이며, 탭 구조나 Hero/News&Events 같은 다중 섹션은 포함되지 않는다.
- "카드 클릭 → 상세 진입 → 수정" 흐름은 현재 계획된 "카드 클릭 시 등록 폼에 값을 채우는
  인라인 편집" 방식과 다르다 (별도 상세 화면 여부는 확장 시 재논의 필요).
- 이 문서의 내용을 실제로 적용하려면 화면 수·데이터 구조(카테고리, 평점 집계, 이슈/할 일 항목 등)가
  늘어나므로, 적용 여부는 Session 6 이후 선택 기능 논의 시 별도로 결정한다.
